# First map Studio test fixes — 2026-10-05

## Asset types and current API behavior

- [InsertService.LoadAsset](https://create.roblox.com/docs/reference/engine/classes/InsertService#LoadAsset) returns a wrapper Model; pcall is required for service/permission failures. Ownership, sharing and OpenUse rules apply. [AssetService.LoadAssetAsync](https://create.roblox.com/docs/reference/engine/classes/AssetService#LoadAssetAsync) is the modern replacement. Its Studio-only `AllowInsertFreeAssets` setting permits public free Creator Store assets from other creators; code cannot enable it. The resolver tries the modern loader, then InsertService for legacy compatibility, never parents loaded content, extracts the nested [Decal.Texture](https://create.roblox.com/docs/reference/engine/classes/Decal#Texture), and destroys the container.
- [DevForum runtime conversion report](https://devforum.roblox.com/t/decal-not-changing-during-runtime/4163541) recommends server-side LoadAssetAsync extraction. [Conversion discussion](https://devforum.roblox.com/t/converting-decal-ids-to-image-ids/2640232/5) documents live InsertService decal support. Studio property-window conversion is not scripted ImageLabel conversion. No legacy numeric offset is reliable; do not subtract IDs or probe neighboring assets.
- [Asset privacy](https://create.roblox.com/docs/projects/assets/privacy) and the [privacy rollout](https://devforum.roblox.com/t/full-release-privacy-for-newly-created-image-mesh-and-decal-assets/4620416) supersede old assumptions that images are universally public. An uploader's personal ownership/group membership does not prove experience permission. Both wrapper insertion and Image delivery can fail independently. Open Cloud requires authorized access; adding credentials or external HTTP infrastructure is unnecessary here. Manual editor extraction plus Config overrides is the durable alternative.
- [DataModel.GetObjects](https://create.roblox.com/docs/reference/engine/classes/DataModel#GetObjects) is an editor/plugin API, used only in the documented command-bar fallback. It is not the runtime solution. [ContentProvider.PreloadAsync](https://create.roblox.com/docs/reference/engine/classes/ContentProvider#PreloadAsync) reports failures in its callback; successful pcall alone does not establish a loaded image. Existing ImageLabel.IsLoaded fallback behavior is retained.

## Spawn lifecycle

[Players.CharacterAutoLoads](https://create.roblox.com/docs/reference/engine/classes/Players#CharacterAutoLoads) must be false before join/respawn loading. It was only assigned during server bootstrap; now the [Rojo project properties](https://rojo.space/docs/v7/project-format/) serialize false too. [Player.LoadCharacterAsync](https://create.roblox.com/docs/reference/engine/classes/Player#LoadCharacterAsync) fires CharacterAdded **before** parenting, rig scaling and final engine spawn placement. RespawnLocation must be a Workspace SpawnLocation with a matching team or Neutral=true.

Existing PlotChooser already handles all twelve map transforms and full occupancy. WorldService catches players present before construction and now schedules each existing player's assignment independently. Profile and plot readiness still gate the first load. RespawnLocation is assigned before loading; existing characters get lifecycle hooks; transient avatar failures retry at most three times; a two-second recovery window catches late displacement. Removal invalidates outstanding work and death triggers one subsequent load.

Read-only inspection of the connected session found PlotCFrame (-177, 4.5, -240), PlotCenter (-182, 0.5, -240), and a camera following the avatar near that plot. Thus assignment exists in that session; the screenshot/log cannot prove which original timing or interaction left the player at the hub. The changes cover startup/placement failure paths; do not claim the original cause was reproduced.
