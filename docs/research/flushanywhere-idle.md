# Auto-flush input and remote presentation

Checked 2026-10-06 before implementation.

- [UserInputService](https://create.roblox.com/docs/reference/engine/classes/UserInputService) provides client InputBegan/InputEnded/InputChanged and focus events. Track keyboard, mouse, touch and meaningful analog changes; include UI-consumed input. A render heartbeat alone is not evidence of input. Coalesce dirty input into a no-argument notification every 15 seconds, and discard unsent input on focus loss.
- [InputObject](https://create.roblox.com/docs/reference/engine/classes/InputObject) documents movement Delta and mouse-wheel direction in Position.Z. Wheel-only input therefore uses Position.Z rather than assuming a nonzero movement Delta.
- [Player.Idled source in Roblox's official docs repository](https://github.com/Roblox/creator-docs/blob/main/content/en-us/reference/engine/classes/Player.yaml): client-only, begins approximately two minutes after idle classification, repeats every 30 seconds, and has no separate resume event. The docs explicitly describe automatic disconnection after at least 20 minutes. A requested 30-minute game guard therefore cannot promise that the Roblox session survives until its prompt. No virtual input, teleport loop or anti-disconnect behavior is implemented.
- [Current DevForum discussion](https://devforum.roblox.com/t/how-does-steal-a-brainrot-have-antiafk/4598164) reports differing idle behavior in other games. This is anecdotal, not a platform guarantee; implementation follows the documented API contract.
- [Client/server boundary](https://create.roblox.com/docs/scripting/security/client-server-boundary): validate payload shape, server state and rate limits. PlayerActivity has no client duration/clock/identity, capacity 1 and refill 0.1/s. The server clock controls expiry and the real flush gate still controls awards. Input telemetry is not proof of a human: an exploiter can imitate valid activity but cannot improve cooldown, RNG, unlocks or currency amounts.
- [Release notes index](https://create.roblox.com/docs/release-notes) and [DevForum release category](https://devforum.roblox.com/c/updates/release-notes/62) were checked; their web extraction provided no substantive release entries. No claim of an exhaustive release-history review or changed idle behavior is made.

The existing reveal controller reuses a single toast and retains only the rarest pending find plus a count. It updates at most once per three seconds, including one trailing update. A compact result never starts water sounds or the world toilet animation. Rarity cues use the existing audio admission limits with an additional 0.25 gain; chat remains an authoritative event observer.
