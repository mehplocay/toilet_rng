# Own-plot spawning and guidance

Checked 2026-10-05 for feature/spawn.

- Disable `Players.CharacterAutoLoads` before startup, including joins. With it disabled, initial characters and respawns require `LoadCharacterAsync`. Keep manual loading in PlotSpawn; start only after assignment and the loaded toilet are ready. [Players](https://create.roblox.com/docs/reference/engine/classes/Players)
- Set `Player.RespawnLocation` before loading to a neutral per-plot SpawnLocation in Workspace. CharacterAdded precedes rig scaling and engine spawn placement, so apply the final facing pivot after LoadCharacterAsync returns. [Player](https://create.roblox.com/docs/reference/engine/classes/Player), [SpawnLocation](https://create.roblox.com/docs/reference/engine/classes/SpawnLocation), [Model](https://create.roblox.com/docs/reference/engine/classes/Model), [DevForum loading-order discussion](https://devforum.roblox.com/t/loadcharacter-on-a-specific-position/2428779)
- Current API marks IsFriendsWith deprecated; use IsFriendsWithAsync server-side with pcall, check departure after yielding, and recompute occupancy before reserving. Failed checks fall back to ordinary assignment. [Player API](https://create.roblox.com/docs/reference/engine/classes/Player#IsFriendsWithAsync), [departure error report](https://devforum.roblox.com/t/feedback-on-playerisfriendswithasync/4289832)
- Platform-change check: Roblox staff announced a client/server friendship patch for late February 2026; later community reports still describe inconsistencies. Do not assume the service cannot fail; live friend accounts remain a QA requirement. [patch announcement thread](https://devforum.roblox.com/t/playerisfriendswithasync-returns-false-for-valid-connections-in-live-servers/4354096), [later reports](https://devforum.roblox.com/t/inconsistent-playerisfriendswith-return/3193480), [release notes index](https://create.roblox.com/docs/release-notes)
- Beam endpoints must be attachments in Workspace; FaceCamera keeps it visible from different directions, Enabled toggles it. Locally created objects make the neon pillar and hub guide owner-only without asset IDs or new remotes. [Beam](https://create.roblox.com/docs/reference/engine/classes/Beam)
- BillboardGui offset sizes remain pixel-sized; MaxDistance limits visibility. Use a local billboard above the larger physical sign so the owner can read their name across the plaza. [BillboardGui](https://create.roblox.com/docs/reference/engine/classes/BillboardGui)
- Tool checks use the existing installed binaries: [Rojo build](https://rojo.space/docs/v7/getting-started/new-game/), [StyLua CLI/check](https://github.com/JohnnyMorganz/StyLua), [Selene](https://github.com/Kampfkarren/selene).

Assumptions: adjacency is the previous/next slot in the current ten-plot ring, with wraparound. Ties prefer clockwise, then counterclockwise, using plot order. The guide runs within 72 horizontal studs of the hub origin and hides within 20 studs of the spawn point. Spawn is five studs in front of the toilet; Teleport uses the same facing CFrame. No progression or reward depends on friendship.

Studio/live QA: join before data loads; concurrent joins/leaves; death/reset and R6/R15/custom avatar scaling; no transient hub spawn; owner-only beacon in two clients; walk hub/near-plot thresholds; Teleport facing; long display names/mobile readability; streaming; real friend accounts and friendship service failures. Headless checks verify chooser/guide logic and construction, not engine physics or replication.
