# Rebirth persistence, input and announcements

Checked 2026-10-05. No player data or secrets were sent in research requests.

- [Creator Hub data stores](https://create.roblox.com/docs/cloud-services/data-stores): UpdateAsync transforms cannot yield and can be retried. Keep the complete reset in a single profile key; construct outside the transform, retry an immutable snapshot, and validate the owned unexpired lease on every transform invocation.
- [Roblox player data guidance](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing) and [Roblox staff guidance on DevForum](https://devforum.roblox.com/t/implementing-player-data-and-purchasing-systems/2839941): session locking prevents overlapping writers. The project already implements this; replacing it with an independent rebirth key would introduce split commits.
- [DevForum session-locking analysis](https://devforum.roblox.com/t/session-locking-explained-datastore/846799): loading before an earlier session finishes saving can regress progress. Rebirth therefore retains the existing per-load token and Close serialization.
- [DataStore errors and limits](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits): requests can yield under throttling and fail. A failed transport response is not evidence that the write did not commit. Do not roll back the swapped profile; stop gameplay on exhausted retries. A hard crash can recover the old or new whole profile, not a cross-key half reset. No exactly-once notification guarantee is claimed.
- [Luau table library](https://luau.org/library/): table.clone is shallow. Reset construction recursively copies the bounded, sanitized profile tree so prior references cannot mutate the replacement.
- [GuiObject](https://create.roblox.com/docs/reference/engine/classes/GuiObject), [UserInputService](https://create.roblox.com/docs/reference/engine/classes/UserInputService) and [GuiService](https://create.roblox.com/docs/reference/engine/classes/GuiService): use button input plus global input-end/focus events and selected-object gamepad input. A two-step hold is a client accident-prevention feature; server requirements and expected level are independently validated. Closing, scrolling, leaving, selection loss and focus loss cancel holds.
- [ProximityPrompt](https://create.roblox.com/docs/reference/engine/classes/ProximityPrompt): the optional stairs prompt only opens the owner window. It cannot grant/reset anything. The remote checks do not trust prompt ownership as authority.
- [TextChannel](https://create.roblox.com/docs/reference/engine/classes/TextChannel): DisplaySystemMessage runs on the client. Rebirth uses the existing bounded server announcement worker, friend checks, opt-out and rate limit, with escaped platform account names and config-only titles.

No inference that recent releases cannot affect behavior: engine QA remains required.
