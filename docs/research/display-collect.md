# Display and collection runtime research

Checked 2026-10-06 for `fix/display-collect`.

- [ProximityPrompt API](https://create.roblox.com/docs/reference/engine/classes/ProximityPrompt): native keyboard/gamepad/touch prompts support explicit activation distance, zero HoldDuration and RequiresLineOfSight=false. Jar uses F/Y, ten studs, no hold; pads use six studs. E/X places/removes a display. Attributes must be set before parenting so streamed client registration sees ownership immediately. Ownership filtering is presentation, not authorization.
- [Client/server boundary](https://create.roblox.com/docs/scripting/security/client-server-boundary) and [network ownership](https://create.roblox.com/docs/physics/network-ownership): client-originated prompts/touches are untrusted. Independently validate player/plot identity, live character, finite distance to the exact server-owned target, slot capacity, lease and shared limiter before mutation. A pad's proximity cannot authorize Collect All.
- [BasePart API](https://create.roblox.com/docs/reference/engine/classes/BasePart): CanTouch must be enabled before connecting Touched. Use the existing anchored, noncolliding pad label anchor as the sensor; decorative meshes stay nontouchable. A touch event does not itself prove proximity.
- [DevForum disabled-prompt report](https://devforum.roblox.com/t/proximity-prompt-gets-triggered-even-if-disabled/4519238) reinforces the need for server authorization even when clients filter Enabled. This is a user report, not an engine guarantee. Existing owner filtering was correct in this source; no confirmed engine defect is claimed.
- [TweenService](https://create.roblox.com/docs/reference/engine/classes/TweenService) and [PointLight](https://create.roblox.com/docs/reference/engine/classes/PointLight): client tweens provide local glow and GUI movement. Reuse the distance-culled idle registry; readiness changes do not create tweens each tick. Stream-out cancels/destroys tween references. Coin flights destroy their instances on completion.
- Platform release-note search did not identify a prompt behavior change that this fix needs. The implementation relies on the current API contract above, not a proposed physics authority feature or an undocumented Enabled security guarantee.
- [Rojo installation/versioned CLI](https://rojo.space/docs/v7/getting-started/installation/) and [StyLua options](https://github.com/JohnnyMorganz/StyLua): build the existing project with `rojo build -o build.rbxl`; format/check Luau with Windows line endings. [StyLua issue 925](https://github.com/JohnnyMorganz/StyLua/issues/925) documents a past line-ending override bug; report the installed version and actual check result.

Persisted accounting stays in 1/6000-coin units. Per-slot collection must debit only its slot; Collect All may pool fractions. Both credit/debit before the immutable save snapshot, never roll back an ambiguous committed save, and publish success only after an acknowledged save with the same profile identity.

[Current DataStore budgets](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits) and [best practices](https://create.roblox.com/docs/cloud-services/data-stores/best-practices) require bounding writes as well as remote traffic. The shared input bucket admits two requests/second, but a separate internal save bucket permits a ten-pad burst and refills at only 0.2/second (12 writes/minute sustained). This keeps walking collection responsive without turning every contact into a durable write. Empty contacts consume neither bucket; a save already in progress cannot enqueue another waiter. Other durable game actions and backend retries still share platform budgets; headless tests do not prove production throughput.
