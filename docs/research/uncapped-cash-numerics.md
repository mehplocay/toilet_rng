# Uncapped cash numeric safety (2026-10-07)

- Luau uses IEEE754 doubles, exact integer range through 2^53: https://luau.org/syntax/ and https://create.roblox.com/docs/luau/numbers . Keep the existing 9e15 wallet/Earned and integer-subcoin bounds; do not treat these as multiplier design caps.
- Check finiteness before multiplication; compare against remaining room / factor before multiplying. Library semantics for floor, huge and formatting: https://luau.org/library/ . The 2025 runtime recap adds isfinite/isnan/isinf: https://luau.org/news/2025-12-19-luau-recap-runtime-2025/ . Retain portable explicit comparisons for the installed CLI and engine doubles.
- JSON/DataStore behavior is not a substitute for validation. Current platform serialization changes: https://devforum.roblox.com/t/changes-to-httpservicejsonencode-and-httpservicejsondecode/4400205 ; current Open Cloud handling: https://create.roblox.com/docs/cloud/guides/data-stores . Reject NaN/inf before income mutation regardless of backend serialization behavior.
- Multipliers remain floating factors, saturating only at the largest finite double if the representation overflows. Ledger products saturate before multiplication at 9e15 in their own units. Base display weights are summed before cash multiplication; proportional allocation never sums unbounded multiplied rates. Do not add 0.5 to integers at or above 2^52: it can round an exact odd integer up.
- Fixed-point persistence remains 6000 subcoins/Coin; settlement and corrected whole-coin division preserve final subcoin tails. Oversized sales are rejected before removing inventory; no batch wrap or silent precision loss.
- Short suffixes extend through Dc, then scientific notation keeps all finite doubles readable. Invalid nonfinite input displays 0 and is never a valid ledger input.
- Tools checked: https://create.roblox.com/docs/projects/external-tools (Rojo build), https://github.com/JohnnyMorganz/StyLua (Luau formatting, Windows line endings), https://github.com/Kampfkarren/selene (lint standard libraries). No new engine API or asset IDs are introduced.
