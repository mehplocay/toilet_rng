# Owner admin authorization

Checked 2026-10-06 for `feature/admin-panel`.

- [Roblox client/server boundary](https://create.roblox.com/docs/scripting/security/client-server-boundary): validate sender permissions, request structure, finite numeric ranges and context on the server; rate-limit before expensive work. Admin commands use a private RemoteEvent, exact whitelisted schemas, per-player buckets, monotonic request IDs and one in-flight command. UI possession is never authorization.
- [Access control and confidentiality](https://create.roblox.com/docs/scripting/security/access-control): replicated scripts can be inspected even when disabled. [ServerStorage](https://create.roblox.com/docs/reference/engine/classes/ServerStorage) does not replicate; [PlayerGui](https://create.roblox.com/docs/reference/engine/classes/PlayerGui) runs LocalScripts. Rojo places the entire admin client under ServerStorage, and the server clones it only into the authorized player's PlayerGui after checking their live profile. Normal State has no admin metadata or backup.
- [Player reference](https://create.roblox.com/docs/reference/engine/classes/Player): use the engine-provided UserId, never Name/DisplayName or a supplied identifier. The current reference marks single-role rank APIs deprecated.
- [GroupService reference](https://create.roblox.com/docs/reference/engine/classes/GroupService): `GetGroupInfoAsync(groupId)` yields, returns `Owner.Id`, and can return nil Owner. The optional group route compares this numeric owner with the sender's UserId under pcall; missing/error results deny. A 60-second per-Player cache bounds lookups, with no concurrent lookup per player and lifetime cancellation after removal. No lower-rank or multi-role membership grants access.
- [Roblox staff on premature rank API deprecation](https://devforum.roblox.com/t/playergetrankingroupasync-deprecated-before-alternative-is-enabled/4675872/3), June 2026: replacement API rollout lagged deprecation warnings. The design uses established group ownership information rather than depending on the rollout or arbitrary single-role selection. [Community ownership platform announcement](https://devforum.roblox.com/t/community-ownership-is-now-managed-at-the-community-level/4687884) is another reason not to infer ownership from role names. Optional group authorization is off by default; the explicit UserId is sufficient.
- [Group API cache discussion](https://devforum.roblox.com/t/does-getroleingroup-getrankingroup-still-cache/2388215): forum observations show stale group results and variable refresh behavior. This is a warning about assumptions, not a guaranteed cache TTL. Our application cache does not promise instant group-owner revocation beyond Roblox's own API freshness. Deploy allowlist changes and retire old servers for immediate operational revocation.

No credentials, profiles or private identifiers were sent in research requests.
