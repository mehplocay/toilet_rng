## Synthesis and metering decisions

- [NumPy Generator](https://numpy.org/doc/stable/reference/random/generator.html) supports explicit seeds. Use explicit PCG64 with independent per-asset seeds. Pin the local NumPy/library versions in the manifest; floating-point/library changes can affect reproducibility across machines.
- [SciPy Butterworth filters](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.butter.html) recommend second-order sections for stable IIR filtering, and [resample_poly](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.resample_poly.html) applies anti-alias filtering when changing sample rates. SciPy was unavailable locally, so this implementation avoids resampling: author at 32 kHz, keep additive partials below 8.5 kHz, restrict FM modulation, shape noise and roll off the mix in the FFT domain.
- [SciPy convolution documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.fftconvolve.html) explains full convolution and FFT efficiency. Our NumPy implementation zero-pads linear convolution to retain the complete finite room impulse. Music note/reverb tails extend beyond the loop, then fold back into the beginning. Periodic mix filtering preserves that circular signal; no musical beats are cut away.
- Design choices: raised-cosine attacks/releases prevent abrupt oscillator edges; decaying harmonic partials suggest keys/plucks; a few inharmonic partials suggest marimba/vibes; filtered, enveloped noise supplies water and a soft kit. Chord inversions, phrase variation, rests, bass approaches, restrained stereo and 7 ms timing humanization keep arrangements from being a repeating scale exercise. These are authored choices, not claims that a library guarantees pleasantness.
- [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/) gives biquad transfer functions. The local meter evaluates a 4 dB / 1.5 kHz RBJ shelf and 38 Hz high-pass on a zero-padded FFT grid, then uses 400 ms gates with 75% overlap and absolute/relative gating. [pyloudnorm documentation](https://github.com/csteinmetz1/pyloudnorm) and its [meter implementation](https://github.com/csteinmetz1/pyloudnorm/blob/master/pyloudnorm/meter.py) explain this measurement approach. We report **LUFS estimates**, not certified compliance; signals shorter than 400 ms get `lufs_estimate: null` plus an ungated K-weighted proxy. Rumble remains intentionally quiet instead of being boosted aggressively to a stinger target.
- Approximate true peak uses four-phase windowed-sinc interpolation. Near-Nyquist energy, DC, clipping, silence, endpoint amplitude and music seam step are checked independently. These checks do not substitute for human listening, device testing or a reference BS.1770 analyzer.

SciPy, soundfile, pydub, matplotlib and pyloudnorm were absent; no standalone ffmpeg command was on PATH.
- A workspace-local pip attempt failed with socket error WinError 10013 (network restricted). No system installation was changed. Rendering requires **only the existing NumPy, Python stdlib and bundled libsndfile 1.2.2**. PNG reports are written directly with NumPy/zlib, with an original tiny bitmap font.
- [python-soundfile](https://python-soundfile.readthedocs.io/en/0.13.1/) documents libsndfile-backed OGG/Vorbis support and known encoder issues. It was researched but not installed or used. [Audaspace writing API](https://audaspace.github.io/bindings/sound.html) was tested through Blender: a 3,200-frame OGG had a correct granule count but `Sound.data()` returned only 3,072 frames locally. Do not use that path for frame-count verification in this environment.
- Blender contains `blender.shared/sndfile.dll`. A small `ctypes` adapter uses the official [libsndfile API](https://libsndfile.github.io/libsndfile/api.html) directly; it returns all 3,200 frames in the same probe. [VBR quality control](https://libsndfile.github.io/libsndfile/command.html#sfc_set_vbr_encoding_quality) is set to 0.5 for every asset. Write/read in 16,384-frame blocks: a single whole-track write caused a stack overflow in the bundled writer, fixed by bounded calls.
- Vorbis container serial numbers are ordinarily random. The generator derives them from each key and recalculates page checksums according to [Xiph Ogg framing](https://www.xiph.org/ogg/doc/framing.html), making the complete output bytes repeatable with the same toolchain. Manifest records both synthesis-PCM and decoded-PCM hashes, plus final file SHA-256.

## Review observations

- The initial ServerEvent decode had an endpoint amplitude near the 0.003 FS limit. Lengthening its attack from 3 to 8 ms reduced the boundary step to about 0.00021 FS without changing its fanfare rhythm or duration.
- A full second render reproduced all 21 final OGG byte hashes and both PCM hash sets. A 1 kHz, amplitude-0.1 mono fixture measured about -23.05 LUFS estimate; duplicating it to stereo added 3.0103 dB. These sanity checks do not certify the meter.
- Waveform/spectrogram review and final measurements are recorded in `docs/audio-assets.md` and `assets/audio/quality-report.md`. No human listening pass or Roblox-side upload/moderation result is claimed.
