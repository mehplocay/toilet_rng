# Mobile UI and safe areas

Checked 2026-10-07 for the phone HUD task.

- [ScreenGui](https://create.roblox.com/docs/reference/engine/classes/ScreenGui) and [ScreenInsets](https://create.roblox.com/docs/reference/engine/enums/ScreenInsets): CoreUISafeInsets excludes device cutouts and Roblox core UI. Keep interactive content in that root; do not add a second fixed top inset. TopbarSafeInsets is the dynamic space *within* the topbar, not a replacement for the gameplay safe rectangle.
- [GuiService:GetGuiInset](https://create.roblox.com/docs/reference/engine/classes/GuiService#GetGuiInset) returns top-left and bottom-right inset vectors. [GetInsetArea](https://create.roblox.com/docs/reference/engine/classes/GuiService#GetInsetArea) returns rectangles relative to CoreUISafeInsets. The existing inset root's AbsoluteSize is sufficient for this layout; calling GetGuiInset again would double-account for space.
- [UserInputService](https://create.roblox.com/docs/reference/engine/classes/UserInputService#TouchEnabled): TouchEnabled describes supported touch input; it is not a phone-size test. Combine it with viewport dimensions. TouchScreenEnabled is a separate hardware capability property; this task retains TouchEnabled.
- [Mobile input](https://create.roblox.com/docs/input/mobile), [UI positioning](https://create.roblox.com/docs/building-and-visuals/ui/positioning-and-sizing-guiobjects), and [ContextActionService](https://create.roblox.com/docs/reference/engine/classes/ContextActionService): mobile movement/jump controls are supplied by Roblox. BindAction's createTouchButton option can create additional action buttons. This HUD uses its existing GuiButtons and does not create another default mobile action button. Reserve the larger thumb rectangles specified by the owner instead of relying on one control skin's exact coordinates.
- [Adaptive design](https://create.roblox.com/docs/production/publishing/adaptive-design) recommends readable small-screen text and adaptive content. [Hardware testing](https://create.roblox.com/docs/performance-optimization/test-on-hardware) explains why emulation does not validate real touch ergonomics. The numerical 44 px targets and 12/14 px text floors are this task's acceptance criteria, not a claimed universal Roblox measurement.
- Platform release: [Notched Screen Support — full release](https://devforum.roblox.com/t/notched-screen-support-full-release/2074324) documents safe-area behavior and warns that Camera.ViewportSize can differ from physical screen dimensions. [Mobile GUI sizing discussion](https://devforum.roblox.com/t/mobile-gui-doesnt-fit-screen/3082510) confirms inset/fullscreen compatibility can affect animations. Use current Creator Docs as the authority; no fullscreen compatibility workaround is added to interactive HUD content.
- Tools: [Rojo build](https://rojo.space/docs/v7/getting-started/new-game/) supports binary .rbxl output; [StyLua options](https://github.com/JohnnyMorganz/StyLua) support Windows line endings. [CLI override issue](https://github.com/JohnnyMorganz/StyLua/issues/925) was checked; explicitly run --line-endings Windows and verify the resulting files.
