## Persistence and economy adversarial review

The current profile contains wallet, inventory, lifetime collection, protected carried copies, displays, upgrades, rebirth/run/lifetime counters, income timestamp/pending units, daily/index claims and preferences in one UpdateAsync record. A GUID per Player lifetime, never merely JobId, owns a 180-second lease. Acquisition consumes offline elapsed time inside the atomic record update. Get and each save callback check ownership/expiry; callback replay cannot overwrite a newer owner. Saves serialize and retry one immutable snapshot four times with 1/2/4-second waits. New-session state cannot be erased by an old Player's cleanup.

The harness covers same-server rejoin, cross-session takeover, duplicate Load, delayed acquisition/save response, before/after-commit errors, replayed callbacks, concurrent gameplay/close and shutdown. Autosave interval is 60s and BindToClose waits up to 25s, including pending loads. Loss is normally the unsaved interval plus backend latency; it is **not guaranteed to be at most 60s**, and even an acknowledged durable transaction can be rolled back by an external administrative restore. Selling, toilet purchases, flushes and preferences are not individually durably acknowledged. There is no current trading or consumable paid currency to export an old unsaved award into another player's account.

Upgrade expectedLevel prevents double debit; daily day/index ID prevent repeat claims; income collection transfers fixed-point units rather than trusting a client timestamp. A rebirth switches to one complete replacement and locks Get until it saves, preserving discoveries/settings/rewards and protected carried copies while resetting the specified wallet/tier/tracks/run/pending fields. Tests cover both old-or-new outcomes after ambiguous save failure, and no second starter bonus. Selling cannot consume first copies, displayed reservations or carried protected stock. Legacy 100 slots retain ten-at-a-time visual pages; new purchases cap at ten. Pending income caps scale with cash and tank (maximum 725,760 Coins/player), with timestamp high-water protection against clock rollback/rejoin replay.

Retire pre-feature server binaries during rollout: old whitelist sanitizers cannot preserve fields they never knew about. No code change in this worktree can repair an already-running old binary. Release to a separate test universe for persistence/Marketplace trials; Studio namespacing does not isolate a published test place in the same universe from production.

## Luck, rare events, identity and purchases

`UpgradeRules:Luck` applies `min(5, toiletLuck * (1 + 0.1*LuckBoostLevel + rebirthLuckBonus) * event * pass * daily)`, validates positive finite factors and clamps before multiplication. Cash is additive with rebirth (maximum 3.6x); FastFlush reduces the base interval before track/rebirth speed and the final 0.4s floor. Current personal paid luck is 1; test-only 2x and extreme factors demonstrate future stacking cannot exceed the cap. The new exhaustive matrix covers 9,856 tier/level/rebirth/boost combinations; existing tests cover independent cash/speed levels and overflow/NaN. Rare-first independent checks always end in Poop fallback. No no-drop path exists; rejection at a numeric ceiling is a rejected flush, not an awarded empty result.

Events originate from the real server award. Flush IDs are deduplicated; the visual event queue is capped at 16 with an 8s broadcast gap. Server luck expiry refreshes rather than multiplying repeatedly. Chat and rebirth share the per-sender 5s cooldown, bounded queue 16, TTL 15s and a single worker. Friendship calls can yield; recipient settings, sender/profile identity and TTL are rechecked afterward. A stalled friendship call delays announcements but does not spawn a worker per message. Queue storage remains bounded. All connected service/player tables are removed on departure; existing cleanup tests cover late entitlement lookups and announcement removal.

`PresentationRules.Name` bounds account identity to 20 ASCII word characters; `Escape` encodes ampersand/angle brackets/quotes. Chat re-resolves catalog IDs and escapes item text; injection tests include markup, newline and invalid bytes. VIP decorates the existing filtered chat prefix, not a client-uploaded badge. Non-chat display labels have RichText disabled. No free-form player text enters the system announcement flow. A client can fake its own chat or VIP label locally; it cannot broadcast an economic result to other clients.

All four pass IDs are zero and developer products are empty. Zero/unknown IDs perform no ownership query or prompt and cannot be granted by a completion event. Positive-ID mock tests cover failed/stale ownership queries, replay and departure. The Roblox server completion is used as a permanent entitlement signal, never proof of another payment; true ownership is not overwritten by an older false query. New idempotence also bounds callback side effects. Ownership errors fail closed and periodic/explicit refresh provides recovery. The receipt guard intentionally never grants or acknowledges any product: enabling products without an atomic durable PurchaseId ledger remains prohibited by the implementation contract, not solved by this guard.

Current duration is shorter than cooldown, so two drops is a conservative allowance. Effect counts reserve all visible showcase positions and conservatively ignore client distance disabling. Idle effects run within 100 studs at a 0.5s registry scan. Each awarded animated flush emits 24 world burst particles: at 30 rolls/s, 720 emitted particles/s before lifetime/distance culling, in addition to idle particles. Local rare effects can emit another 24; reveal UI has at most one active effect and two queued data entries, with bounded confetti/rays, one cinematic item viewport and explicit camera/tint cleanup. Particle count is not fill-rate: transparent overlap, beams, bloom, water and GUI layers need GPU profiling.

Most UI modal frames and layered vector fallbacks remain allocated while hidden; ancestor-visible count is neither draw calls nor a text-layout measurement. The UI fixture includes Studio-only developer controls and a partly discovered collection; it is a reproducible sample, not the maximum possible UI tree. Collection cards are lazy/diffed and 20 repeated State updates allocate no new cards. 37 512x512 RGBA icons would be about 37 MiB without mipmaps or 49.3 MiB with a full mip chain **if all used uncompressed at full resolution**; this is a storage arithmetic scenario, not measured Roblox memory. Mesh textures, decoded audio, engine/core UI, render targets and terrain add costs. Shared mesh instances do not duplicate all vertex/texture storage. Do not multiply triangles by an invented bytes-per-instance estimate.

At the 0.4s floor, 12 players can award 30 flushes/s: 60 direct RemoteEvents/s (State + Flush Result), plus 2.4 IncomePending messages/s and occasional events/settings. The 1,200-award real-handler fixture confirms exactly 2,400 direct messages. Its simple profile produces a **1,203-byte State + 182-byte result JSON-equivalent proxy**: roughly 3.46 kB/s per player or 41.55 kB/s aggregate at the floor. Roblox's binary wire format, framing/compression, fuller inventories/legacy 100-slot displays and replicated moving models are excluded; this is not a bandwidth measurement. Summing remote buckets also permits bounded additional preference/display/sale traffic. Invalid outbound FireServer calls have no handlers and no relay amplification.

Server work estimates: 120 auto eligibility visits/s, about 12 actual income settlements/s (timestamp-gated), player-list refresh of 12 players/s, three sorts of <=12 rows every 10s, 12 periodic pending refreshes/5s, and <=12 routine autosaves/minute plus durable actions. Legacy display pages can rebuild ten stands per player each 10s; normal ten-slot plots do not rebuild on this timer. Ordinary unchanged State now performs zero descendant recounts. A valid display-toggle adversary can still cause up to 240 stand rebuilds/s over twelve players; this is the main remaining allocation stress case.

The Luau CLI fixture measured **0.09-0.11 ms per flush** (world/network are mocked, engine services absent). At 30/s and an assumed 60 server frames/s that corresponds to **0.045-0.055 ms/frame of CLI-equivalent handler work only**; it is not a forecast of Roblox server frame time. Animated awards may have up to 24 concurrent CFrame tweens; duration 0.32s at maximum cadence gives about 19.2 active on average. At 60Hz, that is about 1,152 average / 1,440 peak PivotTo callbacks/s, plus replication, and primitive fallback models move more parts. A useful frame model is `base engine cost + handler work + active tween/PivotTo cost + replication/physics + amortized UI-independent loops`; its unknown terms cannot be honestly filled without MicroProfiler. Test synchronized max-speed flushes, display toggles, joins/leaves and the ten-second leaderboard/page tick on a 12-player Studio server before assigning a millisecond budget.

## Streaming and remaining release checks

Workspace streaming is enabled, min radius 128, target 512, PauseOutsideLoadedArea and now explicit Opportunistic. The 432x624 main island can mostly reside at the hub; reducing radius would visibly change distant geometry and was not done. Only 25 skyline placements are persistent; coastline collision uses separate floor/wall proxies and boundary assemblies, not a persistent whole-world model. Source templates in ReplicatedStorage are still replicated irrespective of Workspace streaming. Character spawn recovery is bounded; streamed prompt/label registries tolerate removal/rearrival. Native teleport pause behavior and actual memory recovery still need traversal on a low-memory phone.

Before release: run real same-account server-hop/outage and shutdown tests in an isolated universe; test paid pass ownership/cancellation/external purchase with real configured IDs; verify rich-text rendering and chat opt-out with multiple clients; profile max-speed flush/display spam and a 30-minute mobile traversal for frame-time percentiles, script/instance heap growth, GPU draw cost and network replication. These are acceptance gaps, not claims of currently exploitable APIs. Audio IDs and paid pass IDs remain placeholders. No unrelated visual redesign, economy refactor or balance change was made.
