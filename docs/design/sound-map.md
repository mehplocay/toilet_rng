## Design and integration contract

`audio:Play("UpgradeBuy")` is the semantic API. `C.Sound(key, amount)` forwards UI cues through the same service, and `C.StopSound(key)` cancels a managed loop. `Audio/Feedback.luau` observes immutable server snapshots/results; it never awards anything. The first snapshot establishes a silent baseline. State-owned cues are not replayed by Result. Visual intensity and quick reveals change presentation timing; saved SFX settings govern sound.

The runtime defines **48 SFX slots plus five music slots**. All 53 now use the exact Dreadlight Studio uploads from `assets/audio/uploaded-ids.json` (21) and `uploaded-ids-2.json` (32), wired on `feature/audio-wiring`. There are no missing slots, orphan uploads or duplicate IDs. [Generator inventory](../audio-sourcing.md) and [new-asset briefs](../audio-new-slots.md) define source lengths and loop requirements. Published moderation/access and audible playback still need validation.

12 managed SFX voices: UI 3, action 4, reward 3, stinger 1, ambient 1. Each row also lists its slot cap/gap; rejected sounds drop immediately without a backlog. A higher-priority cue can preempt a lower-priority voice if a class/global budget is full. Equal/lower stingers never interrupt an active stronger cue. Two extra positional world flush voices are independently bounded, admitted only within 65 studs of the camera. At 0.4 s flush cadence, sequence gating deliberately skips some plumbing layers while every result remains visible.

Gain in the slot table is the source gain before the class multiplier and SFX slider (default 0.70), not a mastering loudness target. Stingers duck music to 0.60 and ambience to 0.25 of the selected mix, restoring with 1.5 s release. Muting/zeroing SFX stops all its voices and invalidates scheduled flush tails. Music mute/zero stops ambience and fades music before pausing; unmute resumes music at its saved position and restores one bed when its cooldown permits. The existing settings retain independent Music/SFX controls; ambience requires both to be audible. Cancellation and teardown release voices for 20 ms before destruction; loops attack over 20 ms after loading. Sound.Ended immediately reclaims naturally completed one-shots.

### Default runtime volume sanity

Effective gain = source gain × class multiplier × slider × duck, before device/master volume. Slot gains retain the authored sound-map relationships; the class trim compensates for louder fanfare mastering. These are gain settings, not measured output LUFS.

## Limits and review assumptions

- DropLanding is a presentation settle at the end of the current nonphysical upward flight. There is no ground-contact event to hook.
- Sale amount comes from consecutive authoritative snapshots; inventory reduction identifies a sale. Rebirth changes are explicitly excluded. A future inventory sink or coalesced snapshot protocol must extend this observer. Sell All with one item intentionally sounds like a single sale.
- Pass outcome mapping uses existing exact server messages because Success=true alone also means prompt opened/already-owned. No server protocol change was made.
- Coming-soon portal prompts are local, feedback-only additions on existing PortalPulse anchors; physical locked display stands remain read-only, with locked feedback on the Collection control.
- The owner's positional replicated Flush is muted. Other players' existing world sound is routed through a quiet capped bus; actual replication ordering/spatial audibility needs Studio testing.
- Empty assets mean offline tests verify routing, scheduling, settings and cleanup rather than audible quality. Headless tests cannot prove source balance, engine tween timing, mobile focus behavior or audio permissions.
